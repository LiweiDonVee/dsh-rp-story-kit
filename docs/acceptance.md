# Validation scope

The implementation checkpoint has automated parser/store/source-integrity, strict seed, document-content, launch/reading, owner transfer and SavedStory coordinator tests; native UI tests use real React components and typed owner boundaries. Native adapter tests cover public persistence arguments, close/cold/resume ordering, owner reads, exact prefixes, inherited counts, cancellation and the narrowly allowed header/end-seed behavior.

Deterministic service/host fixtures exist only under tests. They do not establish native tool acceptance, model quality or actual rc.3 cross-home recovery. Their event envelopes use public Session types; no test fixture is shipped as a production runtime/provider.

Required final integration evidence uses actual accepted Database0.2/LastStep0.3/GM0.1, optional Context0.2 and unchanged Loop0.1 packages in isolated official DSH 0.2.1-rc.3 homes. It must include normal generic opening through real tools, current adopted reading export, real content/document pack providers, native sidebar/full/narrow screenshots, truly separate-home saved restore, cold process restart, original-prefix equality and fork/rollback within imported ancestry. Historical tool/fact/model counters must stay unchanged during recovery.

Package hashes and local command results are recorded in the coordinator-facing checkpoint report. Remote CI and real native acceptance are reported only when actually run. Publication follows independent review and the coordinated whole-stack gate.
